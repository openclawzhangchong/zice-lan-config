## 1 出厂闸门 `--selftest`：32 条全 PASS

跑法：`build.ps1` 出包后自动执行，报告落 `bin\selftest.txt`。关键断言不是空壳，钉的是真值：

- `order_network_byte_value`：`ToNetworkOrder("192.168.168.21")` 必须等于 363374784（SendARP 要的字节序），写反字节序立刻红。
- `candidates_reserve20_count/bounds`：候选必须正好 234 个、首 21 尾 254、且不含 1 和 20；保留区关掉（填 0）必须回到 254。
- `arp_table_parse`：用真实中文表头的 `arp -a` 片段做夹具，要求只留下 2 条本网段主机，本机地址、广播 `ff-ff-…`、别的网段（`192.168.1.1`、`192.168.137.2`）必须被丢掉。
- `netsh_set_address_exact`：整条命令逐字符比对 `interface ip set address name="以太网" static 192.168.168.21 255.255.0.0 192.168.168.1`；不带网关时不许留尾空格；名字里的引号必须转义。
- `classify_*` 七条：ping 通=占用、只有第二次 ARP 应答也算占用、静默=空闲、本机探测失败=不明（绝不判成空闲）、ICMP 被本地拦但 ARP 有应答仍算占用。
- `picker_*` 五条：固定种子抽 50 次必须全在空闲集合内、至少出现 2 个不同值（防止「永远取第一个」）、永不重复选中本机当前地址、空集合返回 -1。
- `file_version_stamped`：读自己 exe 的文件属性，FileVersion 必须是 1.0.0.0（漏盖版本属性就红）。

## 2 变异测试：闸门确实会红

## 5 尚未真跑的路径（明确标出）

`是(Y)` 之后的 **netsh 下发 + 写后回读 + 网关复检**，以及 **`恢复自动获取 IP（回退）`**，都**没有在这台机器上真跑过**——改的是本机网卡地址，会瞬断网络、掉远程会话，按约定要机主点头指定时机。已经覆盖到的部分：命令串逐字符断言（第 1 节）、`netsh interface ip show config name="以太网"` 用中文名可正常读到配置（退出码 0）、确认框与取消路径（第 4 节）。第一次真跑请当着人做，并准备好回退按钮。


## 6 验证期间的环境变动（不是本软件造成的）

- 17:5x 首查：`以太网`，`192.168.168.200 / 255.255.0.0`，网关 `192.168.168.1`，DNS `114.114.114.114`。
- 18:1x 之后：同一块网卡变成 `192.168.168.220 / 255.255.255.0`，DNS `223.5.5.5,223.6.6.6`，`DHCPEnabled=False`（静态）。
- 19:0x 再查：又变成 `192.168.168.201`。这台机器的地址在整个验证过程中被外部反复改动，与本文档一样，本软件每次跑的都是只读模式。

本软件全程只跑只读模式（`--scan` / GUI 扫描），没有调用过 `netsh`，所以以上是外部改动。教训记录：WMI `Win32_NetworkAdapterConfiguration.Index`（本机 10）和 ipconfig 用的 `InterfaceIndex`（本机 7）是两套编号，一度被我误读成「网卡索引变了」；软件里两者分开存，界面只报 ifIndex，与 `ipconfig` / `Get-NetIPAddress` 对得上。

## 7 v1.3 轮次（配入 `zc-IPFreeScanner` v1.2 的功能后）

### 7.1 扫描提速：先分段计时，再动判据

| 构建 | 并发 | ping 段 | ARP 段 | 总计 | 分类结果 |
|---|---|---|---|---|---|
| v1.0（每空闲地址 2 次 SendARP） | 64 | 7.9 秒 | 50.7 秒 | 58.7 秒 | 空闲 189 / 占用 45 / 不明 0 |
| 只把并发提到 128 | 128 | — | — | 56.8 秒 | 空闲 189 / 占用 45 / 不明 0 |
| v1.3（扫描阶段 1 次 SendARP） | 64 | 7.5 秒 | 28.4 秒 | 35.9 秒 | 空闲 189 / 占用 45 / 不明 0 |

- 128 并发只快 2 秒 ⇒ 瓶颈不在线程数，已回退到 64。
- ARP 段占 86% ⇒ 根源是「每个空闲地址再发一次 `SendARP`」。改成一次后，**同一网段同一时刻的分类结果与改前逐条一致**，交叉复核仍零矛盾——因为 ping 本身会触发 ARP 解析、结果落在系统 ARP 表里，扫描前读它做种子，第二路 L2 信号并没有丢。
- **写入前的 2 次 `SendARP` 复测原样保留**，没有为了提速动最后一道门。
- `--scan` 与 GUI 日志现在都输出 `ping_ms` / `arp_ms`，以后再谈提速先看这三段落在哪。

### 8.3 这一轮抓到的两个坑都在我自己的代码里

1. **CLI 只认 `--flag 值` 不认 `--flag=值`**：结果第一次跑的分辨率矩阵五张全出成默认 1920x1080 黑底白字，看着像「自适应没生效」。修成两种写法都支持，并加 `cli_reads_inline_and_spaced_flags` 断言。
2. **`TryParseSize` 用 `out` 参数**：解析失败时把调用方刚读到的屏幕尺寸清零，一度被我误判成「WinForms 读不到分辨率、要加 GDI 兜底」。改成 `ref` 语义（失败绝不动原值），加 `cli_size_parse_preserves_screen_on_failure` 断言；GDI 兜底仍保留作为第二来源，并在日志里写明用的是 `winforms` 还是 `gdi`。
3. 另外补了 `Program.Main` 的 `[STAThread]`（WinForms 硬性要求，此前缺失）。

顺序上仍是先怀疑自己的脚本、再怀疑产品：这两条都是先复算参数、发现「五张图一模一样」不符合公式预期，才回头查解析器。

### 8.4 v1.4 仍未真跑的路径
